Huginn — Monad Validator API Architecture

Epoch-Based Uptime Indexing

Historical uptime tracking with zero data loss guarantees

Real-Time Layer

Validator node logs are parsed in real-time via journalctl. Every finalized block and timeout event is captured per round, per validator.

uptime_events48-hour rolling window
Insert rate~1 second batch flush
DeduplicationUNIQUE(validator_id, round)
Used by24h live uptime API

Historical Layer

At every epoch transition (~5.5h), all events since the last snapshot are aggregated and permanently stored per validator.

uptime_epoch_snapshotsPermanent storage
TriggerEpoch transition event
GranularityPer epoch, per validator
Queries30d / 90d / all-time SUM
Data Flow
Node Logs finalized / timeout
➔
logger.js parse + batch
➔
uptime_events 48h rolling
➔
Epoch Trigger snapshot-job.js
➔
epoch_snapshots permanent
➔
30d / 90d / All cumulative SUM

Safety guarantees: Events are never deleted before being snapshotted. If no snapshot exists, cleanup is blocked. The epoch watcher runs independently, ensuring snapshots are captured even across server restarts.
